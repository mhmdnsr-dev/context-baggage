# Data Model

## Device

Representative fields:

```yaml
id: d_...
name: ...
os: linux
arch: amd64
createdAt: ...
```

The primary device ID is random and application-specific. It is not derived from MAC address, disk serial, CPU ID, or another sensitive hardware fingerprint.

## Workspace

Representative fields:

```yaml
id: <workspace-id>
name: <project-name>

identity:
  type: git-remote
  value: <repository-url>

localPaths:
  - <project-path>

sync: false

createdAt: ...
updatedAt: ...
```

`id` is the canonical Context Baggage workspace identifier.

`name` is human-readable display metadata. For a Git workspace with a usable remote, the name is derived from the normalized repository identity's final path segment. For example, `git-remote:example.com/org/example-repo` displays as `example-repo`.

`identity` describes the best available workspace identity input:

- `git-remote` uses a normalized remote such as `example.com/org/example-repo`; this supports the same workspace ID across different local paths and operating systems.
- `git-local` means the directory is a Git repository without a usable remote. There is no portable repository identity in this case; the workspace ID is generated by Context Baggage and the Git root basename is display metadata only.
- `local-directory` means the directory is not a Git repository. The workspace ID is generated by Context Baggage and the directory basename is display metadata only.

`localPaths` are metadata. They are not the workspace identity.

For non-Git and no-remote Git workspaces, Context Baggage does not automatically infer cross-machine equivalence from matching directory basenames. Explicit linking is deferred beyond `v0.1`.

## Task

```yaml
id: <task-id>
name: <task-name>
workspaceId: <workspace-id>
status: active
createdAt: ...
updatedAt: ...
```

## Checkpoint

Checkpoints are append-only JSONL records:

```json
{
  "type": "checkpoint",
  "timestamp": "...",
  "deviceId": "<device-id>",
  "message": "<checkpoint-message>"
}
```

## Handoff

Handoffs are Markdown files with these sections:

```text
Completed
Current State
Decisions
Next Steps
Relevant Files
Blockers
```

## Agent Inventory

Agent inventory contains sanitized discovered metadata such as detection state, config paths, high-level MCP server names, skills/instruction file paths, and warnings. It must not contain secrets, credentials, cookies, authentication headers, tokens, passwords, or API keys.

## Sync State

Sync state tracks:

- configured folder;
- last push timestamp;
- last pull timestamp;
- `baseHash`, the last portable state known to be shared with the configured sync folder;
- last push/pull hashes for status and compatibility.

Sync state is local machine configuration. It is not used as the portable device identity for another machine.

## Logical Filesystem Layout

```text
<context-baggage-home>/
│
├── config.yaml
├── device.yaml
│
├── inventory/
│   ├── claude/
│   └── codex/
│
├── workspaces/
│   └── <workspace-id>/
│       ├── workspace.yaml
│       └── tasks/
│           └── <task-id>/
│               ├── task.yaml
│               ├── checkpoints.jsonl
│               └── handoff.md
│
└── sync/
    └── state.yaml
```
